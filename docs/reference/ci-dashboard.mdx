This page tracks the documentation CI pipeline: which checks run, and the
pass/fail of the code blocks on **every** page. The per-page table below is

(`extract_code_blocks.py --run`) on the self-hosted Strix Halo runner.

## How the pipeline works

| # | Stage | What runs | Where |
|---|-------|-----------|-------|
| 1 | Ownership | `check_owners.py` + `generate_codeowners.py` (fail if `CODEOWNERS` is stale) | cloud |
| 2 | Model tables | `fetch_models.py` refreshes the Vision/LLMs/Audio tables | cloud (weekly) |
| 3 | Code blocks | `extract_code_blocks.py` - python syntax (cloud) + on hardware: **run** python/powershell/cmd; **run bash via WSL**; **compile** C/C++ (g++/gcc via WSL); **lint** json/yaml/toml/cmake | cloud + Strix Halo (+ WSL) |
| 4 | Report | `report.py` writes the per-page table (below) + `CODE_TEST_REPORT.md` | runner |
| 5 | Links + prose | `mint validate`, `mint broken-links`, Vale, cspell | cloud |
| 6 | Record | `record_run.py` appends the run to `ci-history.json` | cloud |
| 7 | Failure routing | `notify_owner.py` opens an issue @mentioning the owner + emails the support DL | cloud |

Every runnable block is tested by default; the only opt-out is the `notest`
fence tag.
