This page tracks the documentation CI pipeline: which checks run, and the
pass/fail of the code blocks on **every** page. The per-page table below is
generated by `.github/scripts/report.py` from a full hardware run
(`extract_code_blocks.py --run`) on the self-hosted Strix Halo runner.

## How the pipeline works

| Stage | What runs | Where |
|-------|-----------|-------|
| Link + build | `mint validate`, `mint broken-links` (internal blocking; external weekly) | cloud |
| Prose + spelling | Vale, cspell | cloud |
| Code blocks | `extract_code_blocks.py` - python syntax (cloud) + on hardware: **run** python/powershell/cmd; **run bash via WSL**; **compile** C/C++ (g++/gcc via WSL); **lint** json/yaml/toml/cmake | cloud + Strix Halo (+ WSL) |
| Report | `report.py` writes the per-page table (below) + `CODE_TEST_REPORT.md` | runner |
| Failure routing | `notify_owner.py` opens an issue that @mentions the page owner | cloud |
| Record | `record_run.py` appends the run to `ci-history.json` | cloud |

Every runnable block is tested by default; the only opt-out is the `notest`
fence tag.
