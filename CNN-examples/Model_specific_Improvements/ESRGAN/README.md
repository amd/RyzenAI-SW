# Real-ESRGAN x4 INT8 for the Ryzen AI NPU

Quantization recipe for Real-ESRGAN x4plus (RRDBNet, 250x250 → 1000x1000) to an INT8 QDQ model for
the VitisAI EP. It uses Olive 0.11.0 + AMD Quark 0.10: UInt8/Int8 MinMSE with power-of-2 scales,
CLE and AdaRound.

## How to run

Set up the two Python environments as described in the [top-level README](../README.md#environments).

Re-quantizing is optional and expensive (see below). To rebuild the model anyway:

```bat
:: quantization env
python calibration_dataset\prepare_calibration_dataset.py --download   :: or --div2k <DIV2K_train_HR folder or zip>
python export_fp32.py               :: writes esrgan_fp32.onnx (SHA-256 6ea2f4d61fa0...)
run_quant.bat --force               :: Linux: bash run_quant.sh --force
```

`run_quant` stops with a message if `output/ryzen_model/model.onnx` already exists, so that the
pre-built model is not overwritten by accident. With `--force` (or `FORCE=1`), it moves the existing
`output/` to `output_prev/` (replacing an older `output_prev/`), deletes `cache/` and runs
`olive run --config olive_ryzen_config.json`. The new model is written to `output/ryzen_model/model.onnx`.
`git checkout -- output` restores the pre-built model. No custom Olive passes are needed.

**Cost of a rebuild:**

- **Minimum RAM: 32 GiB; 48 GiB recommended.** A controlled one-image run peaked at 20.24 GiB
  process RSS (21.68 GiB increase in total system memory use). The measurement machine had 64 GiB.
- **Temporary space: about 175 GB.** Quark's MinMSE calibration writes the calibrated activations of
  every calibration image to its temporary folder, about 17.6 GB per 250x250 image, so about 175 GB for
  the 10 images. By default this is the system temp folder (`%TEMP%` / `/tmp`). Point `TEMP`/`TMP`
  (Windows) or `TMPDIR` (Linux) to a large disk before running, or add `"TmpDir": "<path>"` to
  `extra_options`.
- **Time: many hours on the CPU.** AdaRound (1000 iterations over 23 RRDB blocks) is the slowest step.

## Quantization recipe

| Item | Setting |
|---|---|
| Activations | UInt8, symmetric, per-tensor, MinMSE, power-of-2 scales |
| Weights | Int8, symmetric, per-tensor, MinMSE, power-of-2 scales |
| Algorithms | CLE (`cle_steps` 6) + AdaRound (`num_iterations` 1000, `batch_size` 4, `learning_rate` 0.1, `early_stop`) |
| Extra options | `EnableNPUCnn`, `ConvertNCHWToNHWC` (the quantized model takes NHWC input), `RemoveQDQMulAdd`, `Int32Bias: false` |
| Format | QDQ, `CPUExecutionProvider` for calibration and AdaRound |

### CPU vs GPU AdaRound

The config runs AdaRound on the CPU: `optim_device` / `infer_device` = `cpu` and `ExecutionProviders` =
`CPUExecutionProvider`. To run AdaRound on an AMD GPU with ROCm, set the two devices to `cuda:0` and the
execution provider to `ROCMExecutionProvider`; all other settings stay the same.

AdaRound results depend on the device and libraries, so builds on different devices are not
byte-identical. The accuracy of a model built with CPU AdaRound has not been measured.

## Calibration

| Item | Value |
|---|---|
| Method | MinMSE (power-of-2 scales) for activations and weights, then AdaRound on the weights |
| Images | 10 images from DIV2K **train** HR (0001–0800), so they never overlap the DIV2K validation images used for accuracy |
| Selection | `random.Random(42).sample(sorted(files), 10)` over the 800 DIV2K train HR files `0001.png`–`0800.png`; each image is saved under its DIV2K name |
| Preparation | Center-crop the HR image to 1000x1000 (bicubic upscale first if it is smaller), then bicubic downsample to 250x250 (Pillow), the same way the accuracy test builds its LR inputs |
| Order | Fixed by `images/manifest.txt` (sampling order); the loader stops if the manifest and the folder list different images |
| Pre-processing at calibration time | `cv2.imread` → center-crop 250x250 (a no-op for the prepared images) → BGR to RGB → /255 → HWC to CHW; no mean/std normalization |

The pre-built model was calibrated with these 10 images in `manifest.txt` order.
`calibration_dataset/prepare_calibration_dataset.py` applies the selection and preparation above. It
reads DIV2K train HR from a local folder or `DIV2K_train_HR.zip` (`--div2k`), or with `--download`
reads only the 10 selected images from `DIV2K_train_HR.zip` on the
[DIV2K website](https://data.vision.ee.ethz.ch/cvl/DIV2K/).

## Accuracy test

`accuracy/esrgan_accuracy_test.py`, run in the accuracy environment:

| Item | Value |
|---|---|
| Dataset | DIV2K validation HR (images 0801–0900), downloaded on first use from `https://data.vision.ee.ethz.ch/cvl/DIV2K/DIV2K_valid_HR.zip` to `~/.cache/esrgan_accuracy_test/` |
| Samples | `-n 100`; 99 images are evaluated (1 is skipped because it is smaller than the 1000x1000 HR crop) |
| Pair construction | HR = center crop 1000x1000; LR input = bicubic downsample of the HR crop to 250x250, /255 |
| Metric | PSNR and SSIM on the Y channel (ITU-R BT.601), plus PSNR on RGB; 4-pixel border crop; average latency per image |

`output\ryzen_model\model.onnx` is the pre-built model; the FP32 model comes from `export_fp32.py`.

```bat
cd accuracy
python esrgan_accuracy_test.py -m ..\esrgan_fp32.onnx             -e CPU   -d CPU -n 100
python esrgan_accuracy_test.py -m ..\output\ryzen_model\model.onnx  -e CPU   -d CPU -n 100
python esrgan_accuracy_test.py -m ..\output\ryzen_model\model.onnx  -e VITIS -d NPU -n 100
```

The first NPU session compiles the model, which takes about 5 minutes; later runs use the cache.

## Results

DIV2K val, 99 images, test setup as in the [top-level README](../README.md#test-setup).

| Model | Runtime | PSNR-Y (dB) | SSIM-Y | PSNR-RGB (dB) | ms/image |
|---|---|---|---|---|---|
| FP32 `esrgan_fp32.onnx` | CPU EP | 25.73 | 0.7762 | 23.94 | 2417 |
| FP32 `esrgan_fp32.onnx` | VitisAI EP, NPU | 25.55 | 0.7742 | 23.78 | 937 |
| INT8 (pre-built model) | CPU EP | 25.87 | 0.7687 | 24.09 | 2077 |
| INT8 (pre-built model) | VitisAI EP, NPU | **25.86** | **0.7690** | **24.08** | **97.97** |

- An FP16 reference on the GPU (DirectML) gives 25.73 dB / 0.7763.
- NPU and CPU EP results for the INT8 model agree within 0.01 dB.
- NPU partition: the whole graph is one NPU subgraph, except the final `fix2float` of `output_transpose`, which runs on the CPU.
- PSNR-Y is slightly above FP32, while SSIM-Y stays about 0.007 below FP32.
