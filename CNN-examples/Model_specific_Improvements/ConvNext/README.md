# ConvNeXt-Tiny INT8 for the Ryzen AI NPU

Quantization recipe for torchvision `convnext_tiny` (ImageNet-1K classification) to an INT8 QDQ
model for the VitisAI EP. It uses Olive 0.11.0 + AMD Quark 0.10, Entropy activation calibration,
CLE, and no fine-tuning.

## Pre-built model

| Item | Value |
|---|---|
| File | `output/ryzen_model/model.onnx` |
| SHA-256 | `69e3853f81996fa3bec2d7b5f53eb4a94a9f91808a6e501d0ba42185a711ffa0` |
| Accuracy | Top-1 77.18% (CPU EP) and 76.20% (NPU), ImageNet-1K val 5k, see [Results](#results) |

You don't need to re-quantize to evaluate the model: run the [accuracy test](#accuracy-test) on
`output\ryzen_model\model.onnx` directly.

## How to run

Set up the two Python environments as described in the [top-level README](../README.md#environments).

```bat
:: quantization env
python calibration_dataset\prepare_calibration_dataset.py   :: writes calibration_dataset\images\
python export_fp32.py               :: writes convnext_fp32.onnx (SHA-256 ee1812af9ff9...)
run_quant.bat --force               :: Linux: bash run_quant.sh --force
```

`run_quant` stops with a message if `output/ryzen_model/model.onnx` already exists, so that the
pre-built model is not overwritten by accident. With `--force` (or `FORCE=1`), it moves the existing
`output/` to `output_prev/` (replacing an older `output_prev/`), deletes `cache/` and `tmp_olive_custom/`,
then runs `olive run --config olive_ryzen_config.json --package-config olive_ryzen/olive_ryzen_config.json`
with `PYTHONPATH=olive_ryzen`. The quantized model is written to `output/ryzen_model/model.onnx`.
`git checkout -- output` restores the pre-built model. The run takes about 1.5 minutes on a 16-core CPU.

Quark may print `CPU version of custom ops library compilation failed` when MSVC (`cl.exe`) is not
installed. The message is harmless.

## Quantization recipe

| Item | Setting |
|---|---|
| Pre-pass | `AMDConvnextFuseConvMul`: folds the per-channel layer-scale `Mul` (after the block's `Transpose`) and any scalar `Mul` before the `MatMul` into the `MatMul` weight and `Add` bias |
| Activations | Int8, symmetric, per-tensor, **Entropy** calibration, static scales |
| Weights | Int8, symmetric, per-tensor, MinMax |
| Algorithms | CLE (`cle_steps` 6); no AdaRound / AdaQuant |
| Extra options | `ConvertNCHWToNHWC` (the quantized model takes NHWC input), `Percentile` 99.999 |
| Format | QDQ, `CPUExecutionProvider` for calibration |

`AMDConvnextFuseConvMul` is a performance step applied before calibration. Each ConvNeXt block ends
with a constant per-channel layer-scale `Mul`, 18 in total. Folding it into the preceding projection is
algebraically identical in FP32, and it removes those `Mul` operators together with their separate
quantization boundaries, so each projection stays a plain `MatMul` + `Add` (a single `Gemm` in the
quantized model). The quantized model still runs if this fold is skipped.

## Calibration

| Item | Value |
|---|---|
| Method | Entropy (KL divergence) on activation histograms |
| Images | 200 ImageNet-derived RGB images (a subset of the Hugging Face `timm/mini-imagenet` train split) in `calibration_dataset/images/`, stored as PNG at original size |
| Order | Fixed by `calib_list.txt` |
| Pre-processing | `cv2.imread` → `cv2.resize` to 224x224 (bilinear, no crop) → BGR to RGB → /255 → ImageNet mean `[0.485, 0.456, 0.406]` / std `[0.229, 0.224, 0.225]` → HWC to CHW |

**The calibration order matters.** Entropy calibration is order-dependent in Quark 0.10. If the same
200 images are fed in numeric file-name order instead of the `calib_list.txt` order, Top-1 on the CPU EP
drops from 77.18% to 72.24% (ImageNet 50k). Reading the folder in `os.listdir()` order gave 70.52%
Top-1 on the NPU (5k). The loader stops with an error if an image listed in `calib_list.txt` is
missing or the folder holds a different number of images. If you calibrate on a different image set,
re-run the accuracy test.

The calibration pre-processing (direct resize to 224x224) differs from the evaluation pre-processing
(short-side resize to 236 and center crop to 224, see below). The results below use the calibration
pre-processing listed above.

## Accuracy test

`accuracy/convnext_accuracy_test.py`, run in the accuracy environment:

| Item | Value |
|---|---|
| Dataset | ImageNet-1K validation, Hugging Face `evanarlian/imagenet_1k_resized_256` (`val` split, streamed) |
| Samples | 5,000 (`-n 5000`), streaming shuffle with seed 42 and buffer 5,000; the full set is 50,000 |
| Pre-processing | Resize short side to 236 (bicubic) → center crop 224x224 → /255 → ImageNet mean/std; NCHW or NHWC is chosen from the model input shape |
| Metric | Top-1 / Top-5 accuracy, average latency per image |

```bat
cd accuracy
python convnext_accuracy_test.py -m ..\convnext_fp32.onnx             -e CPU   -d CPU -n 5000 -s 42
python convnext_accuracy_test.py -m ..\output\ryzen_model\model.onnx  -e CPU   -d CPU -n 5000 -s 42
python convnext_accuracy_test.py -m ..\output\ryzen_model\model.onnx  -e VITIS -d NPU -n 5000 -s 42
```

The first NPU run compiles the model (cached afterwards). For NPU partition statistics, set
`DEBUG_LOG_LEVEL=info` and `XLNX_ONNX_EP_VERBOSE=2` and look for `No. of Operators` in the log.

## Results

ImageNet-1K val, test setup as in the [top-level README](../README.md#test-setup).

| Model | Runtime | Top-1 % (5k) | Top-5 % (5k) | Top-1 % (50k) | Top-5 % (50k) | ms/image |
|---|---|---|---|---|---|---|
| FP32 `convnext_fp32.onnx` | CPU EP | 78.00 | 94.70 | 78.57 | 94.59 | 16.9 |
| INT8 (pre-built model) | CPU EP | 77.18 | 93.74 | 77.18 | 93.63 | 17.2 |
| INT8 (pre-built model) | VitisAI EP, NPU | **76.20** | **93.56** | **76.61** | **93.52** | **1.88** |

- An FP16 reference (DirectML) gives 77.96% Top-1 (5k).
- NPU partition: 893 operators on the NPU, 2 on the CPU (the output `DequantizeLinear`), 1 NPU subgraph.
- CPU EP latencies are indicative only.
- 50k values: CPU EP on Linux; NPU on Windows.
