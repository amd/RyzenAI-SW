# DETR-ResNet50 INT8 / UInt16 for the Ryzen AI NPU

Quantization recipe for Hugging Face `facebook/detr-resnet-50` (COCO object detection, static 800x800
input) to a mixed-precision QDQ model for the VitisAI EP. It uses Olive 0.11.0 + AMD Quark 0.10.

The model is split at the transformer input (`/model/Transpose`), after the ResNet-50 backbone and the
input projection. The CNN trunk is quantized to XINT8 (Int8, power-of-2 scales, MinMSE). The
transformer tail uses UInt16 activations / Int8 weights (Percentile). The two parts are merged again, and
BF16 casts are added at the two precision boundaries.

## How to run

Set up the two Python environments as described in the [top-level README](../README.md#environments).

```bat
:: quantization env
python calibration_dataset\prepare_calibration_dataset.py   :: writes calibration_dataset\images\
python export_fp32.py               :: writes detr_resnet50_fp32.onnx (SHA-256 4d11385bcd82...)
run_quant.bat --force               :: Linux: bash run_quant.sh --force
```

`run_quant` stops with a message if `output/ryzen_model/model.onnx` already exists, so that the
pre-built model is not overwritten by accident. With `--force` (or `FORCE=1`), it moves the existing
`output/` to `output_prev/` (replacing an older `output_prev/`), deletes `cache/` and `tmp_olive_custom/`,
then runs `olive run --config olive_ryzen_config.json --package-config olive_ryzen/olive_ryzen_config.json`
with `PYTHONPATH=olive_ryzen`. The custom passes write their intermediate models to `tmp_olive_custom/`
in the model folder. The quantized model is written to `output/ryzen_model/model.onnx`.
`git checkout -- output` restores the pre-built model.

**Disk space: about 260 GB of free temporary space is needed.** Quark's MinMSE calibration of the
trunk writes every calibrated activation of every calibration image to its temporary folder, about
1.3 GB per image at 800x800. By default this is the system temp
folder (`%TEMP%` / `/tmp`). Point `TEMP`/`TMP` (Windows) or `TMPDIR` (Linux) to a large disk before
running, or add `"TmpDir": "<path>"` to `extra_options` of both Quark passes. With too little space,
calibration fails with `OSError: ... requested and 0 written`.

A full run takes about 40 minutes on Linux (the two Quark passes take 1,224 s and 972 s).

## Quantization recipe

| Step | Passes | What it does |
|---|---|---|
| 1. Clean-up | `AMDONNXSIM`, `AMDRemoveConstOp`, `AMDONNXRuntimeOptimize` | onnxsim, `Constant` nodes to initializers, ORT basic graph optimization |
| 2. Split | `AMDDetrSplitModel` at `/model/Transpose` | Trunk = backbone + input projection; tail = transformer encoder/decoder + heads |
| 3. Trunk | `QuarkQuantization` on the trunk | Activations Int8, symmetric, per-tensor, **MinMSE** (`MinMSEModePof2Scale: MostCommon`); weights Int8, symmetric, per-tensor, MinMax; CLE 6 steps; `EnableNPUCnn`, `ConvertNCHWToNHWC`, `Int32Bias: false` |
| 4. Tail | `QuarkQuantization` on the whole model, then split again to keep the tail | Activations **UInt16**, asymmetric, per-tensor, **Percentile** 99.999; weights Int8, symmetric, MinMax; CLE 6 steps; `ConvertNCHWToNHWC`, `OptimizeModel`, `AdjustBiasScale: false`; 190 `TensorQuantOverrides` set the quantization axis of transformer MatMul weights and biases |
| 5. Merge | `AMDDetrMergeModel` | XINT8 trunk + UInt16 tail in one graph |

The custom passes exist because the two halves of DETR use different quantization schemes: the ResNet-50
trunk uses XINT8 (Int8, symmetric, power-of-two scales) and the transformer tail uses UInt16
activations with Int8 weights. Quark applies one quantization configuration per run and Olive runs its
passes in sequence, so the recipe quantizes the two parts in separate runs and joins them afterwards.
`AMDDetrSplitModel` and `AMDDetrMergeModel` do the split and the merge, and `AMDDetrStoreModel` /
`AMDDetrRedirectModel` save and reload the intermediate models between the steps.

The clean-up passes simplify the graph before the trunk is split out. The tail quantization reloads
the model saved after `AMDONNXSIM` and before `AMDONNXRuntimeOptimize`, so that optimization does not
change the tensor names used by the `TensorQuantOverrides`.

`AMDDetrAddBF16QDQ` inserts a QDQ pair (reusing the calibrated scale and zero point) at two points:
the trunk/tail boundary (`/model/Transpose`) and after the last decoder LayerNorm. **Trunk/tail boundary:** the Int8 scale is a power of two, so dequantized values are exactly representable in BF16 and no precision is lost. **After the last LayerNorm:** the UInt16 scale is not a power of two, so the activation is rounded
 to BF16.

The `TensorQuantOverrides` are keyed on tensor names of the exported FP32 model (for example
`onnx::MatMul_4617`). The q, k, v and out projection weights use axis 0 (per input channel) on
purpose. The other overridden weights use axis 1. A different torch / transformers / onnx version can
rename them, so keep the versions in `requirements_quant.txt` and check the export hash. The split and
BF16/QDQ passes also use exact node names, so an export with a different hash can make them fail or
modify the wrong node.

## Calibration

| Item | Value |
|---|---|
| Method | MinMSE (trunk, XINT8) and Percentile 99.999 (tail, UInt16); both use the same images |
| Images | 200 images from COCO 2017 **val** (Hugging Face `detection-datasets/coco`, revision `cf0b22332314a937e9dc8a1957b21725430bb41d`, streaming shuffle, seed 42, buffer 1,000), saved as `0.png` … `199.png` |
| Order | `os.listdir()` order of `calibration_dataset/images/` (not pinned) |
| Pre-processing | `cv2.imread` → `cv2.resize` to 800x800 (bilinear, aspect ratio not kept, no padding) → BGR to RGB → /255 → ImageNet mean `[0.485, 0.456, 0.406]` / std `[0.229, 0.224, 0.225]` → HWC to CHW |

The images are the first 200 samples of that shuffled stream (with `datasets==4.0.0`), saved without
any processing as RGB PNG by `calibration_dataset/prepare_calibration_dataset.py`.

Because the calibration images come from COCO val, they are part of the set used for the accuracy
test (200 of 4,952 images). A calibration set from COCO train would avoid this overlap but has not been
evaluated.

## Accuracy test

`accuracy/detr_resnet50_accuracy_test.py`, run in the accuracy environment:

| Item | Value |
|---|---|
| Dataset | COCO 2017 val, Hugging Face `detection-datasets/coco` (`val` split, streamed) |
| Samples | `-n 5000` with streaming shuffle (seed 42, buffer 5,000); the split has 4,952 images, so all of them are evaluated |
| Pre-processing | Resize to 800x800 (bilinear, no padding, the model has no `pixel_mask` input) → /255 → ImageNet mean/std |
| Post-processing | Softmax over the 92 classes; per query, the best of the 91 object classes (queries whose best class is the background class 0 are dropped); score threshold 0; normalized boxes scaled to the original image size |
| Metric | COCO bbox mAP with `pycocotools` (mAP@[.5:.95], mAP@.5, mAP@.75, AP small / medium / large), average latency per image |

```bat
cd accuracy
python detr_resnet50_accuracy_test.py -m ..\output\ryzen_model\model.onnx -e CPU   -d CPU -n 5000 -s 42
python detr_resnet50_accuracy_test.py -m ..\output\ryzen_model\model.onnx -e VITIS -d NPU -n 5000 -s 42
```

## Results

COCO 2017 val, 4,952 images, test setup as in the [top-level README](../README.md#test-setup).

| Model | Runtime | mAP | mAP@.5 | mAP@.75 | AP S / M / L | ms/image |
|---|---|---|---|---|---|---|
| INT8 (pre-built model) | CPU EP | 0.322 | 0.544 | 0.324 | 0.119 / 0.335 / 0.517 | – |
| INT8 (pre-built model) | VitisAI EP, NPU | **0.288** | **0.510** | **0.282** | 0.085 / 0.293 / 0.498 | **17.4** |

- Rebuilds from the recipe are not byte-identical to the pre-built model; a rebuild gave mAP 0.322 (CPU EP) and 0.287 (NPU).
- An FP16 reference gives mAP 0.380 / mAP@.5 0.572.
- The NPU is about 0.034 mAP below the CPU EP on the same model; most of the loss is on small objects.
- NPU partition: 2,728 operators on the NPU in 3 subgraphs; 1 on the CPU and 8 on VITIS_EP_CPU.
